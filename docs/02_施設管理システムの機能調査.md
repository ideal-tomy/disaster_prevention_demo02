# 施設管理・ビルメンテナンスで使われているシステムの機能調査

作成日: 2026年9月9日
用途: 施設管理システムのデモ制作用の下地資料

---

## 1. システムの地図

「施設管理システム」と一言で呼ばれているものは、実際には5つの層に分かれている。どの層の話をしているかがずれると、相手と話が噛み合わない。

| 層 | 何をするか | 使う人 | 代表例 |
| --- | --- | --- | --- |
| ① 建物制御 | 空調・電気・熱源を実際に動かし、警報を出す | 中央監視室の設備員 | Metasys、savic-net、BAS/BEMS各社 |
| ② 現場入力 | 点検の記録をその場で取る。写真を残す | 巡回する人、清掃スタッフ | 点検アプリ、チェックシートアプリ |
| ③ 保全管理（CMMS） | 設備台帳、点検計画、不具合、修繕履歴 | 現場責任者、保全担当 | MENTENA、ANDPAD BM、点検マスター、おまとメンテ |
| ④ 業務管理 | 案件、顧客、見積、請求、シフト | 事務、営業、経営者 | ビルメンHUB、プロワン |
| ⑤ 資産・FM | 長期修繕計画、コスト、スペース、資産台帳 | 経営、総務、自治体の営繕 | FM-Integration、Archibus、BIMMS、PPS |

中小のビルメン会社が実際に困っているのは②③④。①は建物側の設備として既にあるものが多く、⑤は大企業と自治体の話。

**デモを作るなら、②③④をまたぐ1本の線を見せるのが刺さる。** 現場で入力したものが、そのまま報告書になり、期限の管理に乗る、という線。

## 2. 機能を細かく分解する

製品名ではなく機能で並べると、この領域のシステムはだいたい次の部品でできている。

### 2-1. 台帳（マスタ）

| 機能 | 中身 |
| --- | --- |
| 物件・建物台帳 | 名称、住所、用途、延べ面積、竣工年、契約内容、担当者、図面 |
| 設備台帳 | 設備の種類、メーカー、型番、製造番号、設置年月、設置場所、更新周期 |
| 設備の階層 | 建物 → 系統 → 機器 → 部品、という親子関係を持たせる |
| 部位・部材 | 外壁、屋上防水、内装など、修繕計画の単位になるもの |
| 二次元コード／QR | 設備に貼り、読み取ると台帳と履歴が開く |
| 図面と現地の紐づけ | 平面図の上に設備の位置を置き、そこから履歴を開く |
| 顧客・契約 | 発注者、契約期間、更新日、単価、請求条件 |
| 人・資格 | 従業員、保有資格、有効期限、配置可能な現場 |
| 協力会社 | 得意分野、単価、発注実績 |

### 2-2. 計画

| 機能 | 中身 |
| --- | --- |
| 点検計画の自動生成 | 周期を登録すると、次回の予定が自動で立つ |
| 法定と自主を分ける | 法律で決まっているものと契約で決めたものを別の層にする |
| 点検と報告を分ける | 「点検を実施した」と「行政に報告した」を別々に持つ |
| 段階リマインド | 期限の60日前、30日前、10日前などに通知する |
| 組織で受ける通知 | 個人宛でなく役割宛に届き、退職・休職で消えない |
| 年間計画表 | 日常・定期・法定を1枚のカレンダーに並べる |
| 中長期の修繕計画 | 10〜30年先までの修繕費を周期と実績から積み上げる |
| 予算の平準化 | 山を崩して年度ごとの支出をならす |
| 優先度の点数化 | 何を先にやるかを基準で採点し、決めた理由を残す |

### 2-3. 現場入力

| 機能 | 中身 |
| --- | --- |
| チェックシート入力 | スマホ・タブレットで選ぶ、数値を入れる |
| Excelの取り込み | 今使っている点検シートをそのまま画面にする |
| 写真の添付 | 入力画面から直接撮り、その項目に紐づける |
| 前回値の表示 | 前回の数値を横に出して、変化を見られるようにする |
| 異常時の分岐 | 異常を選ぶと、追加の入力項目と写真が必須になる |
| オフライン入力 | 電波の入らない機械室や地下でも入力できる |
| 引継ぎ記録 | 交代時の申し送りを残す |

### 2-4. 不具合から修繕まで

| 機能 | 中身 |
| --- | --- |
| 不具合報告 | 現場から写真つきで上げる |
| 修理依頼の一元管理 | どの依頼が今どこで止まっているかを一覧にする |
| 承認ワークフロー | 依頼 → 見積 → 承認 → 発注 → 完了、をシステム内で回す |
| 放置案件のアラート | 一定期間動いていない案件を検知して通知する |
| 部品・在庫の連動 | 修理に要る部品の在庫を、依頼画面から確認する |
| 複数拠点の在庫横断検索 | 別の現場にある部品を探す |
| 消耗品の管理 | フィルターなど、交換周期のあるものを切らさない |

### 2-5. 書類

| 機能 | 中身 |
| --- | --- |
| 点検報告書の自動生成 | 入力した内容がそのまま所定の様式になる |
| Excel／PDF出力 | 発注者の指定様式に合わせて出す |
| 月次報告書 | 実施した作業、見つかった不具合、次月の予定をまとめる |
| 見積書 | 項目を選ぶと単価が入り、自動で計算される |
| 請求書 | 完了した作業から変換して発行する |
| 発注書 | 協力会社に出す。法定の記載事項を満たす |
| 過去書類の検索 | キーワードと日付で探す |

### 2-6. 人の配置

| 機能 | 中身 |
| --- | --- |
| シフトのカレンダー | 物件ごとの作業予定とスタッフの空きを1画面で見る |
| ドラッグで配置変更 | 急な欠員に、その場で当て直す |
| 変更の自動通知 | 変わったことがスタッフに届く |
| 資格との突き合わせ | その作業に必要な資格を持つ人だけを候補に出す |
| 稼働状況 | 誰が今どこにいるか、今月何時間動いたか |

### 2-7. 可視化

| 機能 | 中身 |
| --- | --- |
| ダッシュボード | 期限が近いもの、止まっている案件、今日の予定 |
| 傾向のグラフ化 | 数値の推移を自動でグラフにして、劣化の傾向を見る |
| 拠点別・建物別のコスト比較 | どの建物に何でいくらかかっているか |
| 予算と実績の対比 | ずれた理由まで残す |
| 老朽化マップ | 設備の年齢を建物単位で色分けする |
| 稼働率・利用率 | スペースがどれだけ使われているか |

## 3. 実際の製品と、その機能

### 3-1. 保全管理（CMMS）系

現場の点検と設備台帳が中心。中小企業でも入るのはこの層。

| 製品 | 提供元 | 提供形態 | 機能の特徴 |
| --- | --- | --- | --- |
| **MENTENA** | 八千代ソリューションズ | クラウド | 点検タスクの自動生成、写真つき報告書の即時共有、承認ワークフロー、修理依頼の一元管理、部品在庫の連動、故障の傾向分析。日々のタスクが自動でリスト化され、異常やチェック漏れはアラートで通知される。複数工場の部品在庫を横断検索できる。最小10IDから。専用AI「Axel」でテキスト入力を数タップに短縮する機能あり |
| **ANDPAD BM** | アンドパッド | クラウド | 設備台帳を「カルテ」にして過去履歴を自動で紐づける。現場のスマホから点検・不具合報告・修繕手配までを続けて行える。点検計画と修繕状況を可視化 |
| **点検マスター** | ベルテクス・テクノロジーズ | オンプレ／クラウド／パッケージ | 今使っているExcelの点検シートをそのまま取り込める。タブレット入力、写真つき記録、図面と設備台帳の管理、点検計画、数値とトラブル状態の自動グラフ化による傾向管理 |
| **おまとメンテ** | 関電エネルギーソリューション | クラウド | 複数施設の設備台帳と履歴を安価に一元管理。二次元コードを読み取って対象設備を開く。全社の設備情報を一括で検索・抽出する「全リスト機能」 |
| **ゲンバト設備管理** | 山善 | クラウド | 点検通知とカレンダーで実施漏れを防ぐ。スマホ入力、結果のリアルタイム共有、文書と履歴の管理 |
| **ビルカン** | FLINTZ | クラウド | 図面の上に設備情報・修繕履歴・報告書・写真を紐づける。図面から現場の状況を見る作り。スマホで書類を作成し、Excel形式でも出せる |
| **Maintenance Station** | 富士電機 | オンプレ／クラウド | 点検実績から最適な点検計画を自動作成。タブレット入力。点検データと連携した故障分析 |
| **FacilityProducer** | TMEIC | オンプレ／パッケージ | 保全情報の一元管理、メンテナンス計画と実績の可視化、ノウハウ共有 |
| **UNIVEAM4** | 日鉄テックスエンジ | クラウド | 多言語対応の検索・統計。スマホとタブレット対応のダッシュボード |
| **eServ** | 横河ソリューションサービス | サービス | 状態監視と診断。保守計画の立案から実施までライフサイクル全体をカバー |
| **BIMSTOK** | — | クラウド | 点検・修繕の情報をBIM/CIMモデルに紐づける。IFC形式をブラウザで操作。「ノート」という記録単位に資料をまとめてモデルと結ぶ。AIがモデルを解析して操作と把握を助ける |

### 3-2. 業務管理系（案件・顧客・見積・請求・シフト）

| 製品 | 機能の特徴 |
| --- | --- |
| **ビルメンHUB** | 清掃・設備管理向け。案件管理、顧客管理、点検カレンダー、見積書作成をまとめている。物件別の法定点検スケジュール、対応履歴、担当者の稼働状況を1つのデータベースで持つ |
| **プロワン**（ミツモア） | 顧客管理、営業管理、見積作成、機器管理、発注管理、スケジュール・作業管理、請求・入金管理、申請承認ワークフロー、写真ファイル管理、レポート・ダッシュボード、現場アプリ。スマホで撮った写真がそのまま点検・修理報告書になる |

**プロワンの導入例（空調設備の会社）** … 機器情報を顧客に紐づけて一括登録し、月400件を超えるメンテナンス案件を一元管理。案件の進捗を担当者別・ステータス別に一覧にして対応漏れを減らした。30日間動きのない案件を自動で検知して通知する仕組みで、放置を防いでいる。

**物流センターの例** … 設備ごとの修繕履歴と故障の間隔を分析し、特定のコンベアが2年周期で壊れていることを突き止めた。計画的に部品を交換する運用に変え、突発修繕が前年比40%減、修繕費の予算超過（10〜15%）が収まった。

### 3-3. FM・資産系

| 製品 | 機能の特徴 |
| --- | --- |
| **FM-Integration**（FMシステム） | 統合データベースを中心に、BIM、図面管理、長期修繕計画、点検、保全管理を連携させる。建物・設備カルテに不具合履歴・点検結果・図面・写真を機器単位でまとめる。長期修繕のシミュレーションは、過去の実績・中期の予算計画・周期を条件に組み合わせて回せる。実績や予算を反映しない条件でも回せる。複数建物の集計を帳票とグラフで出す。更新や修繕の時期を手で動かしながら計画を作り直せる |
| **Archibus**（BIPROGY） | 世界的に使われている統合型。CAD・BIM図面と連動して部署ごとの面積配分や賃料按分を自動計算。土地建物のポートフォリオと賃貸借契約の一元化。エネルギー使用量の可視化と法令遵守状況の把握 |
| **FmWorks**（ジョンソンコントロールズ） | セントラル空調だけでなく個別空調（VRF）、電気、衛生、昇降設備までを一元管理。他社のビル管理システムが入った建物でも使える。引継記録機能と消耗品管理機能があり、複数の設備管理者が交代する現場で漏れを防ぐ。保全記録と点検記録から中長期保全計画と修繕計画を作る |
| **HUE Asset**（ワークスアプリケーションズ） | 日本の税制・会計基準に準拠した減価償却計算、IFRSにも対応。バーコードやRFIDを使った現物棚卸。建設仮勘定から本勘定への振替管理 |
| **Beacapp Here** | ビーコンで人の居場所を自動検知する。予約した席に座っていないことを検知して空予約を自動キャンセル。曜日・時間帯ごとの利用率をヒートマップにする |

### 3-4. 自治体・公共施設向け

| 製品 | 機能の特徴 |
| --- | --- |
| **BIMMS** | 地方公共団体の情報管理と保全業務を支援するために国が開発したシステム。全庁での情報共有と標準化が狙い |
| **PPS 公共施設計画保全管理システム**（Dynacad） | 施設単位のカルテ表示で保守・修繕の現況を一度に把握。仕様、事故故障、修繕履歴の管理。写真を含む文書をドラッグ＆ドロップで登録。CSV／Excel出力。統合認証（LDAP）対応。**修理修繕の優先度を点数で評価する機能**があり、誰がどの基準でどう評価して決めたかを示せる形にしている（説明責任のため） |

自治体向けで特徴的なのは、機能そのものより「決めた理由が後から辿れること」が要件に入る点。

### 3-5. 建物制御（BAS／BEMS・中央監視）

建物側に最初から入っている設備。ビルメン会社が導入するものではないが、設備員が毎日見ている画面なので、デモで「現場が見ているもの」を描くときに要る。

主な機能は4つ。

| 機能 | 中身 |
| --- | --- |
| 発停操作 | 機器の起動と停止を操作する |
| 状態監視 | 設備の運転・停止状態をリアルタイムで表示する |
| 警報監視 | 異常を検知して警報で知らせる |
| 計測・計量値表示 | 温度・湿度・圧力などの計測値、電力・水道・ガスの積算値を表示する |

構成は、監視用PC・監視装置・制御コントローラ・UPSなどからなる中央側と、コントローラ・センサー・自動弁からなる現場側に分かれる。現場側は熱源機やポンプの台数制御、空調機の冷温水弁・VAV・インバータ制御を担う。

代表的な製品にジョンソンコントロールズのMetasysがある。中央監視と空調・照明の自動制御に加えて、テナントごとの個別操作ができる。BACnet MS/TPのようなオープンな通信規格を使うと、後から拡張しやすくなる。

最近は、データをクラウドのサーバーに送って個別機器の状態を遠隔で把握するサービス（遠隔監視）や、省エネ診断への活用が広がっている。スマホやタブレットから閲覧・操作できるものもあり、巡回や常駐の時間を減らす方向で使われている。

## 4. 費用と導入期間の相場

### 費用

| 形態 | 初期費用 | 月額 | 備考 |
| --- | --- | --- | --- |
| クラウド | 無料〜数十万円 | 数万円〜数十万円 | 導入は数日〜数週間 |
| オンプレミス | 100万円以上（数百万円になることも） | 保守費のみ | 導入は数か月〜半年以上 |

機能追加や外部システム連携を頼むと、別にカスタマイズ費用がかかる。

### 導入期間

| 工程 | 期間 |
| --- | --- |
| 要件定義・製品選定 | 1〜2か月 |
| 契約・詳細設計 | 1か月 |
| データの整理と移行準備 | 2〜3か月 |
| システム設定・カスタマイズ | 1〜2か月 |
| 試運転・研修 | 1か月 |

本稼働まで合計で半年程度。データが整っていてカスタマイズが少なければ3〜4か月。多拠点だと1年を超えることもある。

**一番時間がかかるのはデータ移行。** 長年ためた施設データには、重複、表記のゆれ、欠落がある。移行前にどこまで整理できるかが、導入後の使い勝手を決める。

## 5. 選定でよく挙がる基準

- 自社の業種に対応しているか（製造業向けとビルメン向けでは要る機能が違う）
- 現場スタッフが直感的に触れるか。マニュアルなしで分かる画面か
- スマホ・タブレットから入力できるか
- 入力項目が必要最小限に絞られているか
- 図面や写真を簡単に添付・閲覧できるか
- 既存の会計・人事システムやIoT機器とつながるか。APIがなければCSVの出し入れが充実しているか
- 無料トライアルがあるか
- 初期費用の有無
- 同規模・同業種の導入実績
- 導入後の問い合わせ窓口

繰り返し言われているのは「高機能なものが最適とは限らない」ということ。判断基準は、現場のスタッフが毎日ストレスなく使えるかどうかに集約されている。ITに不慣れなスタッフが多い前提で選ばれている。

導入後の定着では、入力のタイミングと責任者、承認フローと権限、異常値が出たときの連絡ルール、問い合わせ窓口を決めておくことが挙げられている。

## 6. 今のシステムで埋まっていない場所

既存製品の機能を並べると、逆に薄いところが見える。デモで狙うならここ。

| 埋まっていない場所 | なぜ薄いか |
| --- | --- |
| **点検と報告を別カレンダーで持つ設計** | 「必要だ」と記事では書かれているが、標準機能として前面に出している製品はほとんどない。多くは点検スケジュールまで |
| **物件ごとにどの法律が該当するかの判定** | 用途・規模・特定防火対象物の区分で決まるのに、判定は人が調べて手で入れている。ここをガイド付きにした製品は見当たらない |
| **資格者の割り当て** | 12条点検は4種類あってそれぞれ資格者が違う。人と資格と有効期限を、点検の割り当てに直接つなげている製品は少ない |
| **通知が個人ではなく役割に届く** | 担当者の退職・休職で通知先が消える問題は指摘されているが、実装として売りにしている製品は見当たらない |
| **記録の保管期限の管理** | 消防は3年、建築物衛生法は5年と法律ごとに違うのに、期限つきの保管管理として持っている製品は少ない |
| **決めた理由を残す** | 自治体向けのPPSにはあるが、民間向けにはほぼない |
| **AIによる判断の支援** | BIMSTOKのAIアシスト、MENTENAの入力支援AIが出てきた段階。画像から危険を拾って知らせる方向はまだ製品として定着していない |

最後の項目は、防災に建て付けた施設管理システムの提案とちょうど重なる。**まだ製品化されていない領域なので、「他社にもある機能」に見えない。**

---

## 7. デモに落とすときの最小構成

第2部（実画面）に並べる画面を3〜4枚に絞るなら、次の組み合わせが業務の順番と一致する。

**案A: 期限の管理を主役にする**

1. **建物の一覧** … 建物ごとに、期限が近い点検と報告が何本立っているかが見える
2. **1つの建物を開く** … 点検の線と報告の線が別々に並び、それぞれ違う日付を向いている
3. **点検を実施する** … スマホの入力画面。前回値が横にある
4. **できあがる書類** … 報告書の様式。ただし「報告を出した」はまだ済んでいないことが分かる

**案B: 異常を見つけてから直すまでを主役にする**

1. **現場からの不具合報告** … 写真つきで上がる
2. **依頼の一覧** … どれが今どこで止まっているか。動いていないものが立って見える
3. **見積と承認** … 誰が承認したかが残る
4. **設備のカルテ** … その設備の過去の履歴に、今回の1件が積まれる

**案C: 防災に建て付ける場合**

1. **施設の一覧** … 避難所になる施設に印がある
2. **点検の履歴** … 「異常なし」が並んでいる
3. **画像からの気づき** … カメラ映像や点検写真をもとに、危ないかもしれない箇所を挙げる。ただし**システムは候補を絞るところまでで、人が確定する**
4. **災害時に開く画面** … その施設が今どういう状態かが1画面にまとまる

案Cは、点検記録デモの応用として作りやすく、かつ既存製品にない領域なので新しく見える。ただし、AIが危険を断定する絵にすると実務者に警戒されるので、絞るのはシステム、決めるのは人、という分担を画面に出す必要がある。
