# 総合体育館コンソール：日本語UI文言の監査と修正案

調査日：2026年9月9日  
対象：`disaster_prevention_demo02`  
成果物：画面文言の指摘一覧・言い換え案・用語統一案。アプリの文言自体は変更していない。

## 1. 調査結果

現状は、短く書こうとして主語・目的語・動作を省きすぎた表現と、開発者向けの説明が利用者向け画面に残った表現が多い。特に次の文言は優先して直したい。

- 「白天」：この文脈では「日中」とする。
- 「業者紙」「点検紙」：書類の名称が分からない。「点検業者の報告書」「紙の点検記録」などにする。
- 「候補を挙げ、現場が押す」：誰が何をするのか分からない。「画像を確認し、対応が必要かどうかを選択します」などにする。
- 「開館に入れる」「開館数に入れない」：集計対象が不明。体育館1棟の中の場所・設備を「開館数」と数えない。
- 「棟の総合」：何の総合か不明。「体育館全体の利用判定」とする。
- 「記録がない場所を、画面が埋めないためです」：画面が場所を埋めるという不自然な説明。「点検記録がないため、利用できるか判断していません」とする。
- 「未確定。岡田が押すまで空欄」：利用者に開発仕様を説明しているうえ、文字が入っているので空欄ではない。
- 「今夜の電源をサブアリーナにする」：場所と電源を取り違えている。言い換えだけでは直せず、意図の確認が必要。

問題は「日本語として不自然」だけではない。「記録がある」と「安全に利用できる」、「画像の確認者」と「開館の確認者」、「データ未連携」と「設備の状態が未確認」が混ざっている。これらは流暢な文にするだけでは誤解が残るため、別枠で扱う。

## 2. 調査方法・範囲・読み方

### 調査範囲

`app`・`components`・`data`配下のTS/TSXを通読し、全8画面のタイトル、説明、ナビゲーション、ボタン、表の見出し、状態ラベル、詳細パネル、帳票、AI固定回答、通知文、placeholder、title属性、aria-label、メタデータを確認した。CSSの生成文字も検索した。

18件の場所・設備データ、3件の画像確認データ、3組のAI問答、未対応入力への返答、帳票2種類、連携8項目も対象。意味の照合に[テーマ別要件定義書](01_テーマ別要件定義書.md)と[ペルソナと仮ナレッジ](04_ペルソナと仮ナレッジ.md)を使用した。

ブラウザでの表示・操作・読み上げ試験は今回実施していない。指摘はソースに定義された表示文字と表示条件に基づく。写真内の焼き込み文字全体のOCR監査は対象外。ただし、画像確認対象の`c3.png`は直接確認した。点検票の文字は判読できず、表示文言の補足だけで点検内容を読み取れる状態にはならない。

企画書や仕様書の内部文章すべてを校正する依頼とは解釈していない。実画面に出る文言を中心とし、仕様書にも同じ問題がある場合は再混入防止のため更新対象として示す。

### 指摘の分類

- **A：修正推奨** — 誤字、不自然な日本語、過度な省略、開発用語の露出。原意を保って直せる。
- **B：意味・仕様の確認が必要** — 対象、根拠、状態、実際の動作が曖昧。推測して確定文にしない。
- **C：改善候補** — 日本語としては成立するが、対象利用者には具体的な表現のほうが分かりやすい。誤用とは断定しない。

優先度は **高：判断・操作の誤解を生む／中：理解を妨げる／低：表記・読みやすさの改善**。同じ文言の重複はまとめ、異なる文脈で別の問題がある場合は別項目にした。「日本人なら誰でも分からない」「日常で絶対に使わない」といった利用頻度の断定はせず、この業務画面での分かりやすさを評価している。

表の掲載箇所はプロジェクト直下からの相対パスと調査時点の行番号。`data/suirei.ts`を以下では **D** と略記する。`reason`は一覧、`basis`は詳細パネル用。ただしインシデントへ遷移する行の`basis`は、現行画面では直接表示されない。

## 5. 用語・文章の統一案

### 画面名と説明文

| 画面 | 推奨タイトル | 推奨説明文 |
|---|---|---|
| ダッシュボード | 施設の状況 | 場所・設備18件の利用状況と、確認が必要な項目をまとめています。 |
| 一覧 | 場所・設備一覧 | 点検・対応状況と利用可否を切り替えて確認できます。 |
| インシデント | 要対応事項 | 当日のカメラ画像と過去の点検記録から、対応が必要な箇所を確認します。 |
| 画像確認 | 画像確認 | 画像を確認し、対応が必要かどうかを選択してください。 |
| 書類 | 点検・開館前の記録 | 開館前の確認事項と設備点検記録を、並べて確認できます。 |
| 連携 | データ連携状況 | 連携済みのデータと、取り込みが必要な資料を確認できます。 |
| AI | AIアシスタント | 点検記録に基づく利用可否や、確認が必要な点を案内します。 |

AI説明には「このデモでは、3つの質問への回答例を表示します」を併記する。「AIが解析します」「資料を検索します」と、実装にない能力を追加しない。

### 同じ言葉に統一するもの

| 概念 | 統一案 | 注意 |
|---|---|---|
| 全体の建物 | 体育館全体 | 「棟の総合」は使わない。「棟」は棟数を数える場面には自然 |
| 建物の営業・公開開始 | 開館 | 設備・外壁には使わない |
| 部屋・設備が使えるか | 利用可否／利用判定 | 開館承認と区別する |
| 管理対象の件数 | 場所・設備18件 | 混合データなので、すべてを「18か所」と数えない |
| 日常の作業 | 点検・対応 | 「保全」は対象者が理解していれば維持してよい |
| 紙の資料 | 紙の点検記録／点検業者の報告書 | 「業者紙」「点検紙」は使わない |
| 紙を整理する | 保管 | 登録・アップロード・転記とは別動作 |
| 画面へ入力する | 記録する／登録する | 押す・返すなど実装の動作だけで説明しない |
| 画像の未判定 | 判定待ち | 設備の利用可否未確認と混ぜない |
| 場所・設備の判定不明 | 利用可否が未確認／判定できない | 「未確認」だけにする場合は見出しで対象を示す |
| 連携がない | 未連携 | 「未確認」と区別する |
| 車両 | 白いバン | 検出分類を併記する場合は「車両：白いバン」 |
| 図 | 配置図（概略） | 「模式」だけで終えない |
| デモ | デモ用の架空データ | LIVE、モック、DEMOの重複を避ける |
| 日中 | 日中 | 「白天」は修正する |

### 状態語は別々の対象に付ける

```text
場所・設備の利用判定：利用可能／条件の確認が必要／利用不可／判定できない
画像確認の結果：判定待ち／対応が必要／問題なし
対応の進捗：未着手／対応中／対応済み
資料の連携状態：取り込み済み／内容を確認中／未連携
```

これは用語設計案であり、現在存在しない状態を文言だけで表示する提案ではない。「対応済み」と「問題なし」は同じ意味ではない。現実装の状態定義を変更する箇所は別途実装が必要。

## 7. 不自然と断定しない語・そのまま残せる文言

次は一般的な日本語または業務用語であり、単語そのものを排除する必要はない。

- 「保全」「動線」「躯体」「剥離」「受水槽」「棚卸」「目視点検」：専門性はあるが造語ではない。必要なら具体名や短い補足を添える。
- 「ダッシュボード」「AIアシスタント」「ナレッジ」「推奨アクション」：ビジネスで使われる。今回の改善提案は対象利用者への分かりやすさのためで、誤用の断定ではない。
- 「どかす」：日常語として自然。現場手順として移動対象・行き先を明確にするため言い換える。
- 「対応が必要」「問題なし」「閉じる」「印刷」「記録日」「確認者」「下書き」「抜粋」：対象や処理範囲が明確なら、そのままでよい。
- 「アリーナ」「サブアリーナ」「機械室」「受水槽」「更衣室」「観客席」「事務室」「備品庫」「前庭」「西側通用口」：対象名として問題なし。利用判定の根拠が十分かは別問題。
- 「台風第14号接近」「非常口の前に備品がある」「2026/09/06 排水溝の目視点検済み」：短いUI文として成立する。無理に長文化しない。
