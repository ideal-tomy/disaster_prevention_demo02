# 総合体育館コンソール — テーマ別要件定義書

初回実装用の正本。市全体の防災施設コンソール（[../../disaster_prevention_demo/docs/01_テーマ別要件定義書.md](../../disaster_prevention_demo/docs/01_テーマ別要件定義書.md)）の横展開。画面に載せる固有名詞・件数・時刻・判定の内訳は [04_ペルソナと仮ナレッジ.md](04_ペルソナと仮ナレッジ.md) だけを正とする。本書ではその数を繰り返さない。

デモの仮称は「総合体育館コンソール」。英語の OS 名は前面に出さない。フォルダ名 `disaster_prevention_demo02` はリポジトリ上の続き番号であり、画面の名前には使わない。

---

## 1. このデモで見せること

自治体は多くの公共施設を持っている。そのうち現場が毎日触るのは、指定管理の **1棟** である。設備の不具合は場所ごとに少しずつ出ている。記録は紙で、機械室とキャビネットに分かれている。今日、この棟を開けるかどうかを、その場で判断することになる。

見せたいのは、保全の点検記録と、開館に必要な情報が同じものだということである。普段の点検が、そのまま「この場所は今日使えるか」の答えになる。

市版は22施設のポートフォリオである。本デモは同じ翠嶺市総合体育館を、場所と設備の一覧に下ろす。防災は入口のまま残してよい。中身はビル管理である。デモの中でその二重性を説明しない。同じ一覧の表示を切り替えて見せる。

もうひとつ、市版と同じ知見継承の流れを入れる。

1. 棟の固定カメラから抽出した静止画に対して、AIが気になる箇所を挙げる
2. 現場が「対応が必要」「問題なし」を入力する
3. その入力が、次に挙がる箇所と、開館の判定理由に残る

インシデント相関は、その記録が写真つきで一本につながる見せ場である。ライブ映像の解析ではない。

## 3. 背景

市版は「防災に建て付けた施設管理」で稟議の入口になる。現場に渡すと、相手が見たいのはビルメンテナンスに近い1棟の運用である。

同じシェルで、行の単位だけを施設から場所へ変える。新しい箱に見えないことが、横展開の条件である。

URLを送って残る形にする。市版のあとに投影して、切替と写真で話せる形にする。

Building OS Console は LP と製品シェルの参考のまま。タワーの断面、在館、駐車場、不審行動の相関は借りない。

## 4. 課題

- 点検記録が機械室とキャビネットに分かれ、開館の朝に開かない
- 「今日開けるか」が、その場の記憶と電話になる
- 固定カメラがあっても、保全と開館が別の仕事に見える
- 現場が、中央監視盤向けの画面を毎日開く前提にはできない

## 6. 題材

架空市は翠嶺市。実在の自治体名と施設名は使わない。件数と時刻は 04。ここでは次だけ固定する。

- 対象は翠嶺市総合体育館 1棟。場所と設備 18
- サンプルインシデントは1本。市版と同じ INC-20260912-007。台風接近下
- 棟の総合は「条件付き」。アリーナは「使える」。動線が塞がれていることと、夜間の電源が確認できないこと
- 判定は4つ。使える / 条件付きで使える / 使えない / 確認できていない。確認できていない場所を必ず残す
- 固定カメラは外周3台。屋内カメラは未接続として残す
- 公民館・庁舎・学校は出さない

## 7. 業務シナリオ

1. 保全の画面で、期限が近い場所が並ぶ
2. 固定カメラの静止画から、気になる箇所が挙がる。現場が対応の要否を押す
3. 台風接近の日、同じ一覧の表示を開館に切り替える。並びと名前は変わらない
4. インシデントを開く。抽出静止画、検出ラベル、平常時の点検が一本になる
5. 同じ記録から、開館前チェックと設備点検記録簿が出る

## 8. 情報アーキテクチャ

```text
LP
 └ コンソールを開く → 統合ダッシュボード
      ├ 設備・場所（保全 ⇄ 開館）
      ├ インシデント相関
      ├ 画像確認
      ├ 書類
      ├ システム連携
      └ AIアシスタント
```

ナビの並びは次のとおり。初期表示のコンソールは統合ダッシュボード。

1. 統合ダッシュボード
2. 設備・場所
3. インシデント
4. 画像確認
5. 書類
6. システム連携
7. AIアシスタント

AIへの入口はヘッダーの「AIに質問」でも開く。

### 8.1 各画面の目的と必須要素

**LP**
- 何のデモかを短く言う。写真が主役。総合体育館の外観
- CTAは「コンソールを開く」と「AIに質問する」
- 機能カード4つ: 俯瞰 / 切替 / 相関 / 点検が次に効く
- 抽象図は置かない

**統合ダッシュボード**
- 全体ステータス、開館判定の内訳、進行中インシデント1本、棟の模式ピン
- タワーの断面フロアマップは置かない

**設備・場所（見せ場）**
- 保全は点検期限。開館は判定
- 並びと名称は不変。変わるのは列と色
- 「使えない」「条件付き」には平常時の点検が付く
- 記録がない場所は「確認できていない」。色を付けて埋めない

**インシデント相関（ビジュアルの見せ場）**
- 左: 時刻つきタイムラインと抽出静止画
- 右: 相関（動線、電源、備品、平常時記録）と推奨アクション
- 検出枠とラベルは実装で画像の上に重ねる。画像に焼き込まない

**画像確認**
- 気になる箇所の候補。ボタンは「対応が必要」「問題なし」
- 押した件数と内訳が出る。次の候補の出方が変わることを画面に残す
- AIは「危険」と書かない。「確認してください」

**書類**
- 開館前チェックと、設備点検記録簿
- 同じレコードから2種類が出る対応が分かること

**システム連携**
- つながっているものと、紙のまま残っているもの
- 100%にしない。残りがあることが前提

**AIアシスタント**
- 最初の質問は「今日、開館できる場所はどこか」に固定した候補を出す
- 回答の数字は 04 と一致させる
- APIは呼ばない。固定の問答

## 9. Must / Should / Won't

### Must

- LPとコンソール。URL単体で紹介兼デモになる
- 設備・場所の保全 ⇄ 開館切替。並びと名称は同じ
- サンプルインシデント1本を、抽出静止画と検出ラベルつきで見せる
- 画像確認で人が「対応が必要」「問題なし」を押せる
- 書類2種が同じ記録から出る
- 確認できていない場所を残す
- 画面の文言は「確認してください」。危険の断定をしない
- デモデータであることの表記
- 固有名詞と件数は 04 を参照する
- 市版と同じ INC ID、同じ時刻、同じ総合体育館

### Should

- ダッシュボードに棟の模式ピン
- システム連携の進捗（接続済み / 確認中 / 未確認）
- AIの固定問答を2〜3本
- 切替時の短い遷移（200ms程度）
- 検出ラベルの確からしさ。ただし検知率・的中率とは書かない

### Won't（初回）

- 抽象図の自動進行と解決後の再演
- スマホ最適化、単一HTML
- AI API、体験コード、Core接続、Demo Definition の実装（v1はモック。定義書の複製は次フェーズ）
- 被災の映像、けが人、崩れた建物
- 検知率、的中率、費用、補助金、導入の流れ
- 顔が判別できる写真、読めるナンバー、氏名、不審者ラベル
- 防犯、監視、という画面の言葉
- ライブ映像の解析演出
- 断面タワーマップ、在館人数、駐車場稼働率、トイレ
- 公民館・庁舎・学校の行と写真
- ROIシミュレータ導線
- 市版との実行時コード共有

## 10. 誠実さの歯止め

- リアルタイムで映像を解析する演出をしない。出すのは、固定カメラから抽出した静止画と、その上に重ねる検出枠まで
- 車両と人物は、検出枠と短いラベルで示す。特定の個人にしない
- AIに「危険」と断定させない。「確認してください」として人に渡す
- 判定できない場所を必ず残す。全行に色が付く絵にしない
- 防犯や監視という言葉を使わない。見落としを減らし、開館の可否を記録から出す、という言い方にする
- 職員が記録を怠っている、という描き方をしない。現場1人と、市の兼務が紙を分けている前提にする
- 災害の被害そのものを描かない。場所、車両、人の位置、点検の期限で表す
- 記載のない場所の点検結果を、画面が自動で埋めない
- 問題をゼロにしない。条件付きと未確認が残る
- アリーナが使えることと、棟が条件付きであることを、同じ画面で両立させる。片方に丸めない

## 11. 横展開

場所の種類と点検項目、開館時の見え方の言葉は設定データに持つ。本体の画面構造には書かない。初回のデータは 04 の総合体育館。差し替え先の対応は次のとおり。実装の設定ファイル化は次フェーズ。

| 相手 | 1棟の中身 | 切替後の見え方 |
|---|---|---|
| 指定管理の体育館 | アリーナ、動線、機械室 | 今日開けるか |
| 市庁舎 | 執務、議会、機械室 | 執務を続けられるか |
| 福祉センター | 居室、スロープ、受水槽 | 通所・入所を続けられるか |

市版との関係: 同じ市、同じ日、同じインシデント。行の粒度だけが違う。知見継承の流れは市版と同じ。画面の言葉だけが違う。

## 12. 成功条件

- URLを開いたとき、紹介ページと、触れるコンソールの両方がある
- 切替だけで、保全の期限と開館の判定が同じ一覧だと分かる
- インシデント画面が、写真と検出枠で本格的なツールに見える
- アリーナは使える、棟は条件付き、が同時に説明できる
- 記録がない場所が、色の付かないまま残っている
- 中央監視盤には見えない。現場が投影して話せる密度である
- 市版を見た人が、同じ体育館だと分かること
