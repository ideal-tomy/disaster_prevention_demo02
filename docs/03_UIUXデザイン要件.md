## 1. コンセプト

中央監視盤の暗いオペ室にしない。指定管理の現場が、会議で投影して説明できる、静かな運用コンソール。大手SaaSと比べられるのは機能の数ではなく、同じ操作がどこでも同じ位置にあることである。

シグネチャーは2つだけ。ここに演出を寄せる。他の画面はこれを邪魔しない密度にする。

1. 設備・場所の「保全 / 開館」トグル。並びと名前は変わらず、期限が開館判定に変わる
2. インシデントの抽出静止画と、その上に乗る検出枠

LPだけ、写真を大きくして価値を短く言う。コンソールの中では説明コピーを足さない。状態、写真、記録、根拠で話す。

借りないもの: 断面タワー、在館、駐車場、不審行動、防犯の赤の連続、Salesforce Blue、オーロラ、マスコット、ストリーク、リーグ、ダークモード。

### 1.1 画面の役割分担

| 面 | 手本 | 取り入れること | 入れないこと |
|---|---|---|---|
| LP | Apple 製品ページ | 1セクション1こと。写真が主役。見出しは宣言。CTAは2つだけ（知る／開く）。余白。注記 | フルブリード黒背景。ヒーローに実績ロゴ。14セクション。価格。事例カルーセル |
| コンソール | Salesforce 製品UI | 同じシェル。表・カード・ピル・バッジ。予測できる操作。WCAG。レコード型のドロワー | メガメニュー、Lookup、商談Pathの虹、Agentforceの虹グラデ、無料トライアル帯 |
| 操作 | Speak | コア操作は全画面で同じ作法。押した直後に結果が出る。通常時は動きを抑える | マイク中心、ストリーク、フルスクリーン報酬、スキップ不可のオンボーディング |

### 1.2 取り入れる原則（目的を崩さない範囲）

**Appleから**

- Product is the hero。LPの主役は総合体育館の写真。イラストで埋めない
- One idea per section。LPのカード4つは、1カード1行のまま増やすな
- Progressive disclosure。詳細はコンソールへ。LPに機能説明を足さない
- CTAは常に2種ペア。塗り（コンソールを開く）と枠またはテキスト（AIに質問する）
- 動きは章の転換と見せ場だけ。常時アニメは置かない
- 本文カラムは絞る。数字は独立して大きく。注記はフッター1行（DEMO、所要約2分）

**Salesforce製品UIから**

- 同じ操作は全画面で同じ見た目・同じ位置（ヘッダー、左ナビ、ページ見出し、主ボタン）
- データは表として読める。列ヘッダ、行ホバー、等幅の期限、空欄は「—」
- 1件を開くと、状態・根拠・次の操作が同じ型（ドロワーまたはインシデント）
- 公式のバリエーションだけ使う。画面ごとに角丸や影を変えない
- 色は意味があるときだけ。フックでテーマを変えられるが、初回は市版トークンを動かさない

**Speakから（学習アプリの遊びは捨て、操作の質だけ取る）**

- Single Primary Action。各画面に「今すること」が1つ見える（切替、確認する、詳細）
- Zero-Gap Feedback。対応が必要／問題なしを押したら、行の文字が即座に変わる。待たせない
- コア操作の作法を固定する。ボタンは動詞（開く、確認する、どかすはコピーのみ。操作は確認する）
- 報酬演出は使わない。完了は行の状態変化だけ。花火・ストリークは禁止
- AIはヘッダーに常駐する（「AIに質問」）。相棒化のマスコットは置かない。根拠は写真と点検行

### 1.3 操作性の原則

1. **予測できる。** 戻る、注意、AI、切替の位置をページで変えない
2. **待たせない。** 切替 200ms。押下の反応は 150ms 以内に視覚が変わる。スピナーは初回置かない（モック）
3. **消さない。** 押した行、未確認の行、DEMO表記は残る
4. **キーボードで辿れる。** Tab 順はヘッダー → ナビ → トグル → 表の行 → 主ボタン。フォーカスリングを消さない
5. **1画面の主操作は1つ。** 設備・場所はトグル。画像確認は2ボタン。インシデントは読む＋詳細へは既に開いている
6. **失敗しても壊れない。** 画像欠落は無地＋ファイル名。枠だけ浮かない。未知のAI入力は04の1行
7. **投影できる。** 1280px でシェルとトグルが同時に見える。クリック領域は 44px 以上

## 2. トークン

市版 [../../disaster_prevention_demo/docs/03_UIUXデザイン要件.md](../../disaster_prevention_demo/docs/03_UIUXデザイン要件.md) の 2.1〜2.4 をそのまま使う。値を変えない。

- `--ink` `#1C2430` / `--paper` `#F4F6F8` / `--surface` `#FFFFFF` / `--line` `#E4E8EE`
- `--muted` `#5E6A78` / `--nav` `#F7F8FA`
- `--ok` `#1F7A4D` / `--warn` `#C47B12` / `--stop` `#B42318` / `--unknown` `#8B93A0` / `--ai` `#5B4DB7`
- Noto Sans JP。数値は等幅。カード角丸 12px。ナビ幅 232px。最小幅 1100px
- ホバー 150ms。トグル 200ms。`cubic-bezier(0.2, 0, 0, 1)`

色だけで判定を伝えない。必ず文字を付ける（使える / 条件付きで使える / 使えない / 確認できていない）。

`--stop` をヘッダー帯の全面に塗らない。全体ステータスは「注意」で `--warn`。

### 2.5 インタラクション状態（SaaSの表に見せるため）

トークンの色は変えない。状態だけを足す。

| 対象 | 通常 | ホバー | フォーカス | 押下 / 選択 | 無効 |
|---|---|---|---|---|---|
| 行 | 白 | `--nav` を薄く | リング 2px `--ai` | 左の印は変えない | — |
| 主ボタン | `--ink` 地または塗り | 15% 暗く | リング | 150ms | 40% opacity。ポインタなし |
| セグメント | 非選択は線 | 面が `--nav` | リング | `aria-pressed` でインク地 | — |
| ナビ行 | 文字のみ | `--nav` | リング | 現在は左 2px `--ink` | — |

影はカードに常時置かない。ホバーで `0 8px 24px rgba(28,36,48,0.06)` まで。ボーダーは `--line` 1px のみ。ガラスはヘッダーに使ってよい（`backdrop-filter: blur(16px)`、背景は `--surface` の 92%）。Apple の黒ナビにはしない。

## 3. シェル

コンソールの全画面で同じ。ページごとに作り直さない。

```text
┌──────────────────────────────────────────────────────────────┐
│ [標] 総合体育館コンソール        LIVE   14:52   注意   [AIに質問] │
│      翠嶺市総合体育館・点検と開館判定  2026/09/12  台風第14号接近   │
├────────────┬─────────────────────────────────────────────────┤
│ 統合ダッシュボード │                                                 │
│ 設備・場所        │              本文                                │
│ インシデント  1  │                                                 │
│ 画像確認     2  │                                                 │
│ 書類           │                                                 │
│ システム連携    │                                                 │
│ AIアシスタント   │                                                 │
│                │                                                 │
│ 翠嶺市総合体育館  │                                                 │
│ DEMO: モックデータ│                                                 │
│ 指定管理の現場    │                                                 │
└────────────┴─────────────────────────────────────────────────┘
```

- ヘッダーは sticky。スクロールしても LIVE・14:52・注意・AIに質問 の位置は変わらない（Salesforce のグローバルナビ、Apple Local Nav の「文脈固定」）
- LIVE は点滅させすぎない。点は `--ok`。モックの現在時刻は 14:52 で固定。秒を進めない
- 「注意」はピル。クリックでインシデントへ。キーボードでも入れる
- 「AIに質問」はヘッダー右端の常設。どの画面からでも1クリック（Speak の常駐小窓に相当。見た目はボタンのまま）
- 件数バッジ: インシデント 1、画像確認の未入力 2。04 の数。数字は等幅
- ページ見出し（h2＋サブ1行）の高さは全画面で揃える。本文の開始位置が跳ねない
- 下部の注記は常時見える。「DEMO: モックデータ」を消さない
- 左下に岡田・高木の名前は出さない。操作した記録の中にだけ出す

禁止するナビ項目: フロア（項目名として）、在館、駐車場、警備、トイレ。棟の模式図はダッシュボードに置いてよい。ナビにはしない。

標の字は市版と同じ「嶺」でよい。別アイコンにしない。検索ボックスは初回置かない（空の検索はSaaSの真似に見えるが、モックでは何も返せず誠実さに負ける）。

### 4.3 設備・場所（見せ場）

トグルが画面の主。初期は保全。

```text

アリーナ          競技場  指定管理     記録済み
東側搬入口        動線    指定管理     今月
機械室            電源    嶺北電設     期限切れ
```

開館に変わる列:

```text
保全 [ ]  開館 [●]

場所              判定              理由（平常時の記録）
アリーナ          使える            2026/09/08 点検済み
東側搬入口        条件付きで使える    車両 白バン
```

行を押すと、Z02・Z03・Z04・Z05 はインシデントへ。それ以外は右ドロワー。値は 04 の 5.1。記録なしは空欄のまま。「異常なし」と埋めない。

ドロワーはレコード型。Salesforce のハイライトパネルを小さくした形。中に新しいナビを増やさない。幅は本文の 40% まで。見出しの下にパス1行。

```text

アリーナ
翠嶺市総合体育館 › 競技場 › アリーナ
[使える]

業者      指定管理
保全      記録済み
根拠      2026/09/08 床とゴールの点検済み
ナレッジ  —
記録日    2026/09/08
確認者    —
写真      —
```

欄の順は 04 の 5.1 と同じ。ピルは開館判定。保全ビューで開いても、ピルは開館判定のまま（列の切替と競合させない）。写真はファイル名だけ。プレビューは置かない。Z12・Z14 は根拠から写真まで「—」。

一覧は製品の表にする。

- 列ヘッダは sticky（表の中だけ。ページヘッダの下）
- 行高は一定。ホバーで行全体が `--nav`
- 期限・判定の数字と日付は等幅
- 空欄は「—」。プレースホルダの「正常」は禁止
- 行全体がクリック領域。文字リンクだけにしない
- 現在行は左 2px のインク。選択色で行を塗らない（切替の色と競合する）

一覧の行に小さく外観を出すなら `e1` のみ。無い行は無地。ゾーンごとの写真は初回作らない。

## 5. トグル仕様

- コントロールは2セグメント。「保全」「開館」。保全が初期
- 並び、ID、名称、行の高さは不変
- 変わるのは、期限の列が判定の列になること、理由列が出ること、行の左の印の色
- 200ms で文字が入れ替わる。行がスライドして並び替えるアニメは禁止
- トグルしても INC-20260912-007 は残る。バッジの 1 は消えない
- URL に `view=upkeep` / `view=open` を付ける。戻ったとき状態を保つ
- 確認できていない行は、開館時も色を塗らない。左の印は破線。文字は必須
- 東側搬入口は、保全が「今月」、開館が「条件付き」。同じ行で色が変わってよい
