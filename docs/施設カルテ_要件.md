## 3. カルテが答える問い

一覧（保全⇄開館）が答えるのは、これまでどおり次である。

> 今日、この場所は開けられるか。

カルテが答えるのは次である。

> この設備について、いつ何があって、いま何で止まっているのか。

分析も予測もしない。散らばっているものを同じ器に入れると、止まっている場所が見える、ということだけを見せる。

## 4. 置き場所（一覧は差し替えない）

左メニューは増やさない。**「設備・場所」の一覧と保全⇄開館トグルは残す。** ここが体育館版のシグネチャーであり、市版の平常⇄災害と対になる。カルテに丸ごと差し替えると、連動の2段目が消える。

```
設備・場所（一覧。保全 ⇄ 開館。18行。先頭はアリーナ）
  └ 行を開く
       ├ いまインシデントへ行く行（Z02・Z03・Z04・Z05）は、初回もインシデントのまま
       └ それ以外は、いまのドロワーをカルテの時系列に厚くする
```

建物そのものの項目（竣工、面積、法令など）は、一覧の上に短い見出しとして1回だけ置いてよい。設備の行を18行の場所一覧と二重に並べて、トグルを隠してはならない。

中層の「設備の行」（発電機、受水槽、外壁…）は、**場所18行の代わりではなく、カルテを開いたときの中身**である。必要なら、一覧の上に「記録のある設備」を数行だけ出して、押すと時系列が開く。トグル付きの18行より上に置いて、切替の主操作を奪わない。

### 4.1 他画面からの入口

戻れること。飛んだ先から元の画面に戻る。

| 入口 | 飛び先 |
|---|---|
| 統合ダッシュボードの該当ピン | その場所の行、または紐づく設備の時系列 |
| インシデントの根拠に出る K-G3 など | そのナレッジの設備の時系列 |
| 書類「開館前チェック」の根拠1〜3 | 各根拠の設備の時系列 |
| 画像確認の各カード | 撮影対象の設備の時系列 |

Z02・Z03・Z04・Z05 の行クリックは、03 どおりインシデントへ残す。カルテへは、インシデント側の K-G3 などから入る。

## 5. 画面構成

投影幅は既存どおり **1280px**。370px・iPhone基準にはしない。トークン、シェル、ナビは既存のまま。

縦の情報は3層。ただし1画面に建物・全設備・時系列を同時に詰め込んで、トグルを押しのけない。

### 5-1. 建物（項目だけ決める。値は04）

出す項目。値は04に書いてから画面へ載せる。本書の数値は仮置きしない。

| 項目 | 04の扱い |
|---|---|
| 施設名 | 既出。翠嶺市総合体育館 |
| 所在 | 既出。翠嶺市 |
| 指定 | 既出。指定避難所 |
| 記録の状態 | 既出。システム連携と同じ 5/8。押すとシステム連携へ |
| 竣工・延べ面積・構造・用途・該当法令 | **未記載。** 04へ足すかどうかを、実装PLANの前に決める。足すまで画面に出さない |

法令を出すなら、建築基準法12条・消防法17条の3の3・電気事業法（自家用電気工作物）を候補にする。数字や施行日をここで作らない。

### 5-2. 設備の行（カルテの中身）

1行が1設備。横は「前回・次回・いまの状態」。色は既存トークン（緑・黄・赤・灰）。

状態の文言は、既存デモから借りる。**新しい5語セットを作らない。**

| 使う | 使わない（新規） |
|---|---|
| 期限切れ、今月、記録済み、記録なし | 期限を過ぎている（意味は同じでも語を増やさない） |
| 対応が必要、問題なし（画像確認） | |
| 確認できていない、紙のまま、確認中、接続済み | 問題なし を保全の期限列に混ぜない |

「紙のまま」はシステム連携の外壁・躯体に既出。行ごと消さない。

並びは、止まっている側が上（赤 → 黄 → 灰 → 緑に相当する既存色）。**場所18行の保全⇄開館は並べ替えない**（03のまま）。カルテ内の設備行だけ、色順にしてよい。

出す設備は04に既にあるものから選ぶ。初回の3パターンは次で足りる。

| 設備 | 04 | 見せたい形 |
|---|---|---|
| 非常用発電機（K-G3、Z05） | 2026/03/18 ファイル。次回 2026/08/28。期限切れ | 途中で点線に変わる線 |
| 受水槽（K-W1、Z06） | 2026/09/01 水位。記録済み。使える | 止まっていない線。点検が続いていること。**等間隔の複数件は04に無い。足すなら04で決める** |
| 外壁（通路側）（K-E3、Z08） | 2026/06/12 剥離。期限切れ。使えない。連携は紙のまま | 空にしない。手入力の記録と、書庫の紙が本体であること |

正常な設備を消さない。受水槽を残す。赤い設備だけにすると、この体育館が異常な現場に見える。

空調（Z14）は04どおり確認できていない。カルテで「問題なし・次回 2026/11/21」と埋めない。

### 5-3. 時系列（主役）

設備を1つ開くと、出来事を古い順に1本の縦線へ。種類が違っても混ぜる。

各行は「日付／種類／中身」の3つだけ。アイコンを増やさない。

種類は5つ。**点検・不具合・修繕・画像確認・期限。** インシデントは種類を増やさず、既存行の参照先にする。

- **期限**だけは人が入力したものではない。日付が来たら線の上に自動で立つ
- 実施の記録がないまま期限が過ぎた場合、その期限の行から次の行までの縦線を薄い点線にする。何も起きていない区間が長さで見える
- 写真がある行はサムネイル1枚。押すと画像確認へ

発電機（K-G3）の例。日付は04のまま。文は誰が何をしたか。

```
2026/03/18   点検        業者の紙を高木（総務）がファイル。次回 2026/08/28
2026/08/28   期限        次回点検日。実施の記録なし
2026/09/09   画像確認    機械室の写真。点検票が貼られたまま（c3.png）
```

2026/09/12 のインシデントは、上記いずれかの参照先（INC-20260912-007）として出す。種類「参照」は作らない。

外壁は空にしない。

```
2026/06/12   不具合      通路側の剥離。市営繕の記録（K-E3）
```

直近の調査紙がシステムに入っていないことは、1行で書く。記録がない場所を正常に見せない。

## 6. データの形

後の全庁版でも同じ形にする。今は1施設IDだけ入る。

```
施設
 ├ 施設ID
 ├ 名称、所在、指定
 └ （竣工・面積・構造・用途・法令は、04に書いてから足す）

設備
 ├ 設備ID（K-G3 など、画面に既出の記号。新しい記号を作らない）
 ├ 名称、種別、場所ID（Z05 など）
 ├ 記録の状態（接続済み／確認中／紙のまま。システム連携と同じ語）
 └ 次回予定日

出来事
 ├ 出来事ID
 ├ 施設ID、設備ID
 ├ 日付
 ├ 種類（点検／不具合／修繕／画像確認／期限）
 ├ 中身（1〜2行）
 ├ 入力した人（高木（総務）など。業者の紙ならその旨）
 ├ 画像（あれば1枚。既存ファイル名）
 └ 参照先（インシデントID、書類の欄）
```

出来事は種類が違っても**同じ配列に入れる**。これが「同じ器に入れる」の実装上の意味であり、全庁で館を並べられる理由になる。

04に無い出来事（受水槽の半年ごとの水質3件など）は、配列の見本としてここで確定しない。足すなら先に04へ書く。

## 9. 全庁版（次のデモ。いま作らない）

複数施設版で先方の「次年度の修繕優先順位」に答える。市版の防災トグルを営繕草案に塗り替えない。防災は入口のまま残す。カルテと同じ出来事の形を、館ごとに持たせる。

守ること。

- 施設IDでカルテが切り替わる
- 設備の行と出来事の形は、どの施設でも同じ
- 「記録の状態 5/8」を施設ごとに持つ。分母分子の差が館ごとに並ぶ
- 揃っている館と揃っていない館の差が、順位の草案に乗せない理由になる
- 草案は出る。確定は職員が押す
- 優先順位も点数も、1施設版の画面には出さない

## 12. 方向性の受け入れ（実装前）

実装に入る前に、次がYesであること。

- [ ] 市版は「災害の日に使えるか」、体育館版は「今日開けるか」、カルテは「いつ何があって止まっているか」と、問いが3つに分かれている
- [ ] 体育館版の保全⇄開館は残る。カルテは行の奥であり、一覧の差し替えではない
- [ ] 総合管理計画は画面に出さず、カルテを見たあとの言葉である
- [ ] 優先順位・点数・ブロックチェーンは今やらない
- [ ] 時系列の主役は点線（何も起きていない期間）である
- [ ] 数値の正本は04。04に無い値は画面に出さない
- [ ] 正常な設備（受水槽）と、紙のまま／期限切れが同居する

実装後の受け入れ（時系列の点線、4か所からの導線、数値の突き合わせ）は、実装PLANに移す。
